# GridCompute — Natural Activity Multiplier Map

The design rule is strict: if the activity would not make sense at $0 sponsor payment, it is not a core commercial mechanic.

| Natural participant activity | Primary hackathon purpose | Other valuable outputs already created | Potential buyer surfaces | Extra participant burden |
|---|---|---|---|---|
| Choose an architecture | Build the project | architecture diversity, tool choices, tradeoffs | R&D, product research | None |
| Choose compute/model/database/solver | Make system work | greenfield adoption, substitutions, switching reasons | infrastructure vendors | None; telemetry only if disclosed/opt-in |
| Integrate GPU/power/cooling APIs | Build control loop | integration friction, docs gaps, failure modes | product/DevEx | None beyond normal build |
| Run public stress scenarios | Improve score | comparative benchmark, robustness, failure map | problem owner, R&D | None |
| Run hidden final scenarios | Fair evaluation | out-of-sample robustness evidence | benchmark buyer | None |
| Ask mentors/help desk for help | Unblock team | recurring product/docs problems | product teams | None if ticket/help is normal UX |
| Abandon/switch a tool | Keep building | competitive loss reasons, workaround map | product research | Optional one-click reason; no mandatory survey |
| Commit code / submit repo | Enter judging | artifact portfolio, technical work evidence | recruiting (opt-in), R&D | Normal hackathon behavior |
| Demo | Compete / explain | product use cases, technical narrative, venture signal | R&D, CVC/VC, recruiting | Normal |
| Continue after event | Finish promising idea | pilot candidates, longitudinal retention/adoption | problem owner, vendor, VC | Opt-in only |

## High fan-out / low burden modules

### 1. Shared hidden-scenario benchmark
One natural activity produces: ranking, robustness evidence, failure information, alternative architectures and technical work samples. It is the strongest R&D multiplier.

### 2. Optional tool marketplace, not forced sponsor tooling
Teams can use sponsor tools because they help. Tool choice then creates real competitive product evidence. A forced tool destroys the study and should be rejected.

### 3. Normal mentor/help channel as friction signal
Categorize help requests at aggregate level. No keystrokes, screens, DMs or private communication capture.

### 4. Repo + demo as opt-in verified work evidence
Employers can access artifacts only if participants opt in. No hidden employability score or person ranking.

## Commercial efficiency rule

Compare offers ordinally on:

**value fan-out** (cash + avoided cost + R&D + research + product + continuation)

against

**burden** (participant attention + research distortion + operational cost).

No fake decimal CommercialEfficiency score is produced until inputs are grounded.
