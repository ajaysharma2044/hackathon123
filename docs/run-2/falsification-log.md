# Run 2 — Falsification Log

## Incumbent: Cornell Decision Grid

**Status:** survives as mechanism; loses as Event-1 public architecture.

Why it survived:
- naturally supports optimization, simulation, adversarial cases and diverse policies;
- Cornell ORIE is a strong capability anchor;
- can be reused inside multiple tracks.

Why it lost:
- public identity is abstract;
- cross-sector datasets create weak comparability;
- product ecosystems fragment by domain;
- account value is harder to package as one anchor commercial product;
- “all expensive decisions” is less legible to students than a concrete AI-infrastructure constraint.

## GridCompute red-team results

1. **“This is just an energy hackathon.”** Rejected. The participant object is an AI system with compute, performance and software constraints; energy/grid is the scarce resource that makes the engineering hard.
2. **“Utilities won't trust student code.”** Correct — and irrelevant if we sell production validation. The product must be parallel solution search/benchmark/failure discovery; production deployment is out of scope.
3. **“Synthetic data makes it fake.”** Partial hit. Public/synthetic data supports fair comparative evaluation, but not the strongest R&D claim. Highest-VOI validation is whether one buyer will provide a realistic scenario pack under terms compatible with a student event.
4. **“Internal teams can do this.”** Correct for implementation. The event's structural edge is max-of-N parallel search, solution diversity and failure information.
5. **“Kaggle/Topcoder can do parallel search cheaper.”** Real substitute. Hackathon only wins if live multidisciplinary building, integration, hardware/software tooling, mentor interaction and demo/continuation add value not captured by an offline leaderboard.
6. **“Cornell is not special.”** Partial hit. Other elite schools can run this. Cornell's real differentiator is the combination of ORIE, power systems/market design, E3RG/POWERWEB heritage, AI/systems and 1,800+ project-team students.
7. **“Commercial layer will ruin participant experience.”** Controlled only if sponsor mechanics remain optional/useful and >=40% of the build surface is genuinely open.
8. **“Sponsor wants exclusivity.”** Reject if it destroys competitive choice/research validity.
9. **“WTP is obvious because budgets are huge.”** False. Observed WTP remains UNKNOWN until a buyer statement, priced LOI, paid pilot, signed sponsorship or contract exists.

## Kill / weaken / strengthen criteria

**Strengthen:** a problem owner says the benchmark would change a real planning/R&D decision, supplies realistic scenarios, and pays/signs a priced pilot.

**Weaken:** buyers like recruiting/branding but cannot name a decision improved by the benchmark; or they require so much private data that the public event becomes operationally unnatural.

**Kill commercial thesis:** 10–15 qualified interviews converge on substitute parity/no budget/no decision relevance, and no paid/price-bearing pilot can be closed.
